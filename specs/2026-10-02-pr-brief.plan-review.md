## Plan review

### High — T3’s linked-issue approach can select the wrong “first” issue

AC-11 requires the first issue reference in PR description order. T3 says to reuse `extractReferences` and implies taking its first issue (`tasks.md:41-43`). But `extractReferences` processes URL references before `#N` references, not by their textual position (`server/src/modules/intent/helpers.ts:128+`). A description beginning with `#12` and later containing an issue URL for `#13` can therefore select `#13`.

Recommendation: add an order-preserving description-only issue parser (or have `extractReferences` retain offsets), and test mixed `#N`, `owner/repo#N`, and GitHub-URL forms where their textual order differs from parser pass order.

### High — `container.prBlast` cannot be constructed as specified

T3 requires a `container.prBlast` getter “wired like `prIntent`” (`tasks.md:41-42`), but `BlastService` requires a non-optional `log` dependency (`server/src/modules/blast/service.ts:8-12`). The container has no request/application Pino logger to supply; the existing Blast route constructs the service using `app.log` (`server/src/modules/blast/routes.ts:18-25`). This design will either fail type-checking or lose the intended logger.

Recommendation: do not put `BlastService` in `Container` unless the container is explicitly given an appropriate logger. Prefer constructing the brief’s `BlastService` in `brief/routes.ts` with `app.log`, matching the existing route.

### High — The seeded e2e brief cannot target an in-hunk line

T6 requires a Review focus item on an “in-hunk new-side line” (`tasks.md:103-105`), and T10 relies on it (`tasks.md:217`). Yet PR #482’s seed creates `pr_files` with paths/additions/deletions only—no `patch` hunk bodies (`server/src/db/seed.ts:245-254`); the schema’s `patch` is where hunk information lives (`server/src/db/schema/pulls.ts:36-44`). The flow can at best exercise the “outside changed hunks” path, not AC-27/28’s line highlight behavior.

Recommendation: seed minimal safe unified-diff patches for the referenced files and select a real new-side line; add a seed-level assertion or targeted test that the selected line parses as an in-hunk row.

### Medium — The 8,000-token guarantee is not satisfiable for all allowed inputs

T5 commits to keeping the title, Intent, and Blast summary untruncated (`tasks.md:74-75`), while AC-13 requires the complete sent input to be ≤8,000 tokens. Those three mandatory sections alone can exceed the budget; the proposed shrink order has nothing left to reduce. T5’s planned oversized test does not cover this case (`tasks.md:82-89`).

Recommendation: define a deterministic failure/degradation policy for an oversized non-truncatable core, or introduce a validated cap for those inputs. Add a test where title + Intent + Blast summary alone exceed 8,000 tokens.

### Medium — AC-10 is only tested in the pure builder, not at the service/LLM boundary

T5 tests that the prompt builder excludes patch sentinels (`tasks.md:83-85`), but T8’s service acceptance checks only that the issue is in the prompt and that logs omit the description (`tasks.md:180-191`). The service obtains `pr_files.patch`, so an integration/wiring error can still pass a raw patch—or hunk-header context—to `completeStructured` while all planned tests pass.

Recommendation: capture `completeStructured.messages` in a T8 service test using patches containing distinct sentinels in both code lines and hunk-header context; assert neither sentinel appears and assert exactly one provider invocation.

### Medium — AC-12’s enabled-agent/skill filtering and exact ordering lack measurable coverage

T8 says `attachedDocPaths` implements D3 (`tasks.md:165`) but its tests cover only duplicate and missing paths (`tasks.md:187-189`). AC-12 additionally requires enabled agents only, enabled linked skills only, creation-time ordering, and attachment/link ordering. Existing repository helpers demonstrate that link and skill enabled flags are separate filters (`server/src/modules/project-context/repository.ts:80-100`).

Recommendation: specify the repository query/order explicitly and add a fixture with disabled agents, disabled links, disabled skills, equal creation timestamps, and overlapping paths; assert the exact prompt document order and skipped list.

No AC is entirely absent from the plan’s AC→task map, but the issues above leave key P1 behavior either incorrect or insufficiently verifiable.

**Verdict: revise before implementation—three high-severity design/fixture defects can break required behavior.**
